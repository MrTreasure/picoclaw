# PWA review — 2026-09-28

Scope: source review of conversation list, deletion, title storage, caches,
route bundling and storage reporting. This is not a mobile browser UX test.

## Changes delivered

- Codex titles can be renamed locally, isolated by authenticated cache scope
  and thread ID. Storage errors remain visible; successful deletion removes
  the local override. Search uses the overridden title and other browser tabs
  refresh overrides through storage events. No server title mutation occurs.
- Preserve source/originator in the list cache to avoid losing origin labels
  while showing cached rows.
- Keep the normal rename dialog copy, as requested.

## Remaining opportunities

1. **Incremental Codex list loading:** session-list-page.tsx currently exhausts
   every thread/list cursor before resolving the network result. Show the first
   page immediately, load subsequent pages on demand, and retain explicit
   search scope. Validate ordering, duplicates, offline tails and deletion races.
2. **Smaller entry bundle:** production JS is about 1.94 MB uncompressed (about
   567 KB gzip). vite.config.ts intentionally disables automatic route splitting
   because of a previous circular-import failure. Investigate explicit lazy
   loading for Codex/settings and heavy rendering code with real navigation
   tests; do not blindly re-enable the known-broken switch.
3. **Complete storage accounting:** local-storage-stats.ts counts Pico message
   records only. Separately report Codex history, list caches and local titles;
   preserve the distinction between estimated payload sizes and browser quota.
4. **Consistent diagnostics and language:** some bulk actions and Codex labels
   still use hardcoded Chinese. Move these into translations, use typed errors
   across transports, and retain enough request metadata to diagnose failures
   without logging message bodies or credentials.
5. **Mobile acceptance coverage:** verify long press versus scroll, dialog focus,
   offline reopening, pending-deletion feedback and refresh/update behavior on
   an actual installed mobile PWA. Unit tests and HTTP asset checks do not cover
   these interactions.

## Deletion investigation

At 11:36:17 and 11:36:18 the Codex service emitted thread/deleted events after
requests 3 and 4 on connection 358. Both previously occupied terminal threads
are absent from the state database afterward. A subsequently reported failure
needs the affected title and exact error to distinguish a different thread
from client-side cache synchronization; no additional conversations were deleted
as part of the investigation.

The follow-up screenshot identifies a different Muse conversation. Nginx logged
502 responses with a 20-byte origin body at 11:37:38 and 11:39:47. On a consistent
SQLite copy, deleting its 4,276 messages took 29.75 seconds due to FTS trigger
scans, exceeding the launcher's 5-second timeout. Aligning FTS rowids with message
IDs reduced the entire deletion to 1.83 seconds; migration took 9.09 seconds.
The live conversation was not deleted during diagnosis.
